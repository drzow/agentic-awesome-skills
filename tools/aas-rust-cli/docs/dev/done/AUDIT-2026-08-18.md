# Audit Report: `aas` Rust MCP Server

- **Date:** 2026-08-18
- **Crate:** `aas` v1.0.1 (`tools/aas-rust-cli`)
- **Scope:** MCP stdio server (`src/mcp/`), CLI (`src/cli/`), store/index/cache/search modules, dependency audit
- **Method:** full source read, `cargo build` / `cargo clippy --all-targets` / `cargo test` (17 passed), `cargo audit`, live JSON-RPC protocol tests against `target/debug/aas mcp`

## Verdict

2 confirmed MCP protocol bugs that break spec-compliant clients, 1 confirmed broken feature (`aas activate`), no exploitable vulnerabilities.

## High — MCP protocol violations (live-confirmed)

### H1. Startup banner corrupts the stdio channel

- **Location:** `src/main.rs:248` (`mcp_server`)
- **Evidence:** first line on stdout is `AAS MCP server starting on stdio...`. JSON-RPC-over-stdio requires stdout to be pure JSON-RPC; official MCP SDK clients fail to parse. Tolerated only by lenient clients.
- **Fix:** `eprintln!` or remove.

### H2. `Notification` is unreachable; `notifications/initialized` gets an error response

- **Location:** `src/mcp/server.rs` (`McpMessage`)
- **Root cause:** `McpMessage` is `#[serde(untagged)]` and `Request.id` is `Option<Value>`, so any message with a `method` deserializes as `Request` (id=None). The `Notification` arm is dead code.
- **Evidence (live):**
  ```json
  {"error":{"code":-32601,"message":"Unknown method: notifications/initialized"},"id":null,"jsonrpc":"2.0"}
  ```
  Two spec violations at once: a response to a notification (forbidden), and an error for a standard method every MCP client sends.
- **Fix:** make `id` required on `Request`; parse notifications separately; silently ack `notifications/initialized`.

### H3. Version mismatch

- **Location:** `src/mcp/server.rs` (`serverInfo`)
- **Evidence:** reports `1.0.0`; `Cargo.toml` is `1.0.1`.
- **Fix:** `env!("CARGO_PKG_VERSION")`.

## Medium

### M1. `aas activate` creates dangling symlinks

- **Location:** `src/cli/activate.rs:67-78`
- **Root cause:** symlinks to `~/.aas/store/skills/<id>`, but the store is a **bare** git repo — verified `~/.aas/store/skills` does not exist. On Linux `symlink()` to a missing target succeeds, so the copy fallback (line 71) never triggers. Users get broken symlinks reported as "Activated (symlink)".
- **Latent second bug:** the copy fallback (`activate.rs:73`) calls `store.get_blob_at_path(skill_id)` which reads only `skills/{id}/SKILL.md` (`src/store/bare_repo.rs:321-324`) — multi-file skills (references/examples/scripts subdirectories) lose everything except SKILL.md.
- **Fix:** extract the full skill tree from the store (new `BareStore::extract_skill(id, dest)` walking the git tree), then symlink or copy the materialized directory.

### M2. `AAS_SKIP_TLS_VERIFY` disables TLS + SSH host-key verification

- **Location:** `src/store/bare_repo.rs`
- **Note:** documented escape hatch, but a MITM on `aas update` could inject a malicious index/skills. Consider scoping to explicit CLI invocation with a louder warning.

## Low

- **L1.** `limit` not clamped to schema max (50 search / 200 filter) in `src/mcp/tools.rs`. Live-tested `u64::MAX`: no crash, bounded by index size. Clamp it.
- **L2.** MCP handlers never call `validate_skill_id` (CLI paths do, `src/utils/path_validation.rs`). Traversal is blocked *accidentally* by index membership + git tree walk (live-tested `../../etc/cron.d/evil` and `/etc/passwd` → "not found in index"). Add validation as defense-in-depth.
- **L3.** Unbounded stdin line length in `src/mcp/server.rs` — a local client can force large allocations.
- **L4.** Parse errors echo serde text to the client (minor disclosure); protocol version `2025-03-26` hardcoded with no negotiation.
- **L5.** `cargo audit`: git2 0.19.0 has 3 *unsound*-severity advisories (RUSTSEC-2026-0183, RUSTSEC-2026-0184, RUSTSEC-2026-0008); no CVEs; 139 crates scanned, no vulnerable dependencies.
- **L6.** Clippy: 22 warnings (bin) / 27 (test) — mostly `&PathBuf`→`&Path`, needless `to_string`, empty format strings.
- **L7.** `src/cli/update.rs` reports `old_skill_count: 0` always (misleading stats); `src/cli/init.rs` hardcodes version extraction.

## What's solid

- Path-validation utils exist and are unit-tested (`src/utils/path_validation.rs`)
- Index schema-version checking (`src/index/reader.rs`)
- Sane LRU/age cache eviction (`src/cache/eviction.rs`)
- Test suite: 17/17 pass
- No secrets in source
